# PastForward

The storefront at [pastforward.shop](https://pastforward.shop): upcycled 12-inch records with album art on the centre label, plus posters, prints and polaroid cards.

The site is custom-built and static. It is hosted on GitHub Pages from `docs/` on `main`. Shopify sits behind it for products, checkout and orders (`shop.pastforward.shop`), with Razorpay taking payment.

```
visitor ──> pastforward.shop (this repo, GitHub Pages)
                │  Add to cart / Buy now
                ▼
            shop.pastforward.shop/cart/<variantId>:<qty>   (Shopify checkout, Razorpay)
```

## Change something

| I want to… | Edit | Then |
|---|---|---|
| Change a fact the site repeats: email, delivery time, free-delivery rule, payment methods, FAQ, policies, page titles | `src/site.json` | build |
| Change a price or a size | `FORMATS` in `build_catalogue.py`, **and the same price in Shopify** | `python3 build_catalogue.py`, build |
| Add a design | drop the image in `img/` named `FORMAT-ARTIST-ALBUM.webp`, add the product in Shopify | `python3 build_catalogue.py`, refresh `shopify_variants.json`, build |
| Change the look or the behaviour | `src/style.css`, `src/*.js` | build |
| Turn on the Meta Pixel | `tracking.metaPixelId` in `src/site.json` (read the note beside it first) | build |
| Turn on the email sign-up and contact form | `forms.endpoint` in `src/site.json` | build |

Never edit files in `docs/` by hand. They are build output and the next build overwrites them. The exceptions are `docs/CNAME` and `docs/.nojekyll`, which the build leaves alone.

## Build, check, ship

```bash
python3 build.py          # writes docs/ (the live site) and dist/ (single-file copies)
node verify_site.js       # checks the live build: every page, phone and laptop, the path to checkout
node verify.js            # checks the single-file build
git add -A && git commit -m "..." && git push origin main
```

GitHub Pages publishes `docs/` a minute or two after the push. The checks need Node with Playwright (`npm i playwright && npx playwright install chromium`), or set `PF_CHROME=/path/to/chrome` to use an installed Chrome. Don't push if either check reports a failure.

## How the site is put together

- **One real page per address.** `build.py` writes a small HTML file for every route (`/`, `/vinyl`, `/product/<slug>`, `/policies/returns`, …), each with its own title, description, share image and structured data, plus a plain-HTML version of the page for search engines, link previews and AI assistants. The app then takes over in the browser, so moving between pages is instant.
- **Assets are separate, cached files.** `docs/assets/app.<hash>.js` and `app.<hash>.css` are named after their content, so a new build is picked up immediately and an unchanged one stays cached. Fonts live in `docs/fonts/`, product images in `docs/img/`.
- **The 3D record** (three.js) loads only on screens 768px and wider that have a real GPU. Phones and machines without graphics acceleration get the CSS record and a plain bestsellers grid.
- **`docs/404.html`** is the app itself, so an unknown address still gets the site and its own "not in the crate" page.

| Path | What it is |
|---|---|
| `src/site.json` | The facts. One place, read by the pages, the FAQ, the policies, the structured data and `llms.txt`. |
| `catalogue.json` | Products, formats, prices, collections. Generated by `build_catalogue.py` from the filenames in `img/`. |
| `shopify_variants.json` | SKU → Shopify variant id. This is what makes Checkout work. If products are re-imported in Shopify the ids change and this file must be regenerated. |
| `shopify_products.csv` | The Shopify product import, written by `export_shopify_csv.js` from `catalogue.json`. |
| `src/core.js` | Cart, checkout link, router, tracking, forms, shared page chrome. |
| `src/routes.js` | Every page: home, catalogue, product, custom orders, story, FAQ, contact, cart, policies. |
| `src/boot.js` | Start-up: what loads first and what waits. |
| `src/style.css` | All styling. |
| `src/vinyl3d.js`, `vinylcrate.js`, `liquid.js`, `wallpaper.js`, `ripple.js` | The WebGL pieces. |
| `brand/`, `photos/`, `fonts/`, `vendor/` | Brand marks, photography, self-hosted type, three.js. |
| `notes/` | Internal working notes. Not published. |
| `verify_site.js`, `verify.js` | The checks. |

## Rules the site keeps

These are enforced by the checks where they can be.

- Nothing on the site says something that isn't true today. Delivery cost, delivery time and payment methods come from `src/site.json` and must match Shopify.
- No invented reviews, numbers or customer photos. The only figures allowed are `₹1.5L+`, `400K+` and `EST. 2025`.
- A form never claims something happened that didn't. Without a form endpoint, the contact and custom-order forms hand the message to WhatsApp or email already written, and the email sign-up is replaced by an Instagram follow button.
- No placeholder text reaches a page (`[CONFIRM]`, `undefined`, `{{TOKEN}}`).
- Every product on the site maps to a Shopify variant, so anything that can be added to the cart can be paid for.
